# Relay

[モバイル環境からのCodexタスク操作とRelay運用](docs/mobile.md)

Relayは、macOSのメニューバーから、MacローカルおよびSSH接続先のWSL上で動作するClaude CodeとCodexの会話ログを読み取り、原文のまま引き継ぐためのデスクトップ常駐インターフェースである。会話の文脈を維持したまま別の作業環境へ渡す操作を支援する。本システムは外部データベース、独自のユーザー認証基盤、有料の外部推論APIを追加せず、ローカル環境のファイルや既存プロセスの通信を利用して動作する。

## 外観と表示設計

外観は白いガラス調を基調とし、Motionによるスプリングアニメーションを用いてパネルの展開や状態遷移を表示する。OSのアクセシビリティ設定である「視差効果を減らす」および「透明度を下げる」に対応しており、設定が有効な環境ではアニメーションの移動量を抑制し、背景の透過度を下げる。Webインターフェース（WKWebView）側はCSSを用いてガラス調の質感を表現し、macOSネイティブのメニューバーポップオーバー（NSPopover）にはOS標準の半透明素材を適用している。

## 技術選定の理由

各技術を採用した理由は以下の表のとおりである。

| 技術要素 | 採用理由 |
| :--- | :--- |
| Swift / AppKit / WKWebView | メニューバー常駐とWebフロントエンドの実装を再利用し、Electronの同梱によるリソース消費を避けるため |
| React | ログの取得状態や送信待機状態に応じたUIの再描画を管理するため |
| TypeScript | 静的型検査により、ホスト間通信やデータ構造の不整合を防ぐため |
| Vite | 開発時の高速な起動とWebアセットのビルドを行うため |
| Motion | スプリングアニメーションを実装し、OSの視差効果軽減設定へ追従するため |
| CSS | Web画面上で白いガラス調の質感とブラー効果を表現するため |
| Lucide | 外部とのネットワーク通信を行わずに統一されたSVGアイコンを描画するため |
| システムフォント | 外部フォント配信サービスへの通信を発生させず、OSの描画処理に委ねるため |
| Node.js組込みHTTP / fs | 外部のnpmパッケージを追加せず、ローカルサーバーの起動とファイル読み書きを処理するため |
| Python標準ライブラリ | 追加ライブラリを導入せず、MacおよびWSLの両環境でログ解析とソケット接続を行うため |
| OpenSSH | 既存のSSH設定、秘密鍵、known_hostsによる検証手順をそのまま利用するため |
| private JSON台帳 | 一時ファイルの作成、fsync、アトミックなrename手順により、単一プロセスによる書き込み時の破損を防ぐため |
| Node.js test runner / Python unittest | 外部テストツールを追加せず、各実行基盤の標準機能で単体テストを完結させるため |
| GitHub Actions / GitHub Pages | 継続的インテグレーションによる自動検証および、実接続を行わない架空デモを公開するため |

## 実装状況と機能の制約

会話ログの取り扱いと送信処理について、実装済みの機能と制約を分担ごとに整理する。

ログの取得と表示に関しては、MacローカルおよびWSL上の会話ログ読み取り、話者別の発言と原文の表示、引用範囲の選択、補足テキストの入力、プレビュー確認、クリップボードへのコピー、ユーザー自身による送信確認、履歴・下書き・設定の保持を実装している。

メッセージの直接送信に関しては、WSL上のCodexについて、既存デーモンのWebSocketおよびRPCエンドポイントへの接続に成功し、`thread/read` により会話がidle状態であることを確認できた場合に限り直接送信を行える。Mac上のCodexにおいても既存ソケットが存在しない場合はクリップボード経由でのコピー利用となる。別プロセスとして会話を直接再開（resume）する処理は行わない。Claude Codeへの直接送信機能は未対応であり、クリップボード経由でコピーして手動で送信する。

利用枠の確認に関しては、Relay独自の利用回数制限は設けておらず、各AIサービス側の契約枠がそのまま継続する。Codexの残量情報は `account/rateLimits/read` またはログから観測したイベントに基づき、出典と取得時刻を併記して表示する。ログファイル内に信頼できる利用枠情報が記録されていない場合は、数値を算出せず「未取得」と表示する。アカウント情報の推測による自動統合は行わない。

## セキュリティと通信制御

ローカル環境内での不正な通信を防ぐため、通信経路と入力検証を以下のとおり制限する。

ローカルサーバーはループバックアドレス（127.0.0.1）にのみバインドし、外部ネットワークからの直接接続を受け付けない。HTTP通信ではHostヘッダーおよびOriginヘッダーの照合、固定の独自リクエストヘッダーの検査を実施し、CookieにはHttpOnly属性とSameSite属性を付与している。さらにContent Security Policy（CSP）を設定し、外部スクリプトの実行を制限する。SSH秘密鍵やAPIトークンなどの認証情報はRelay内に複製して保存しない。GitHub Pages上に公開しているデモ環境は静的な架空データのみを表示し、実環境への通信は行わない。また、ユーザーの生会話を含む台帳ファイルは公開リポジトリへ含めない運用とする。

## 動作要件と起動手順

動作に必要な環境は以下のとおりである。
- macOS 14以降
- Node.js 22.13以降
- Python 3
- Xcode Command Line Tools（ネイティブアプリのビルド時に必要）

Webサーバーの起動手順:
```bash
npm ci
npm run build
npm start
```
起動後、ブラウザから `http://127.0.0.1:4318` にアクセスする。

デモおよびテストの実行:
```bash
npm run demo
npm test
```

ネイティブアプリケーションのビルドと起動:
```bash
npm run native:build
open build/Relay.app
```
生成されるネイティブアプリケーションはローカル環境向けのアドホック署名のみを行っており、Appleによる公証は実施していない。

## 環境変数とデータ保存先

環境変数の設定により動作条件を変更できる。
- `RELAY_DEMO`: `1` を指定すると架空デモモードで動作する。
- `RELAY_PORT`: 待受ポート番号を指定する（既定値: `4318`）。
- `RELAY_DATA_DIR`: データ保存ディレクトリのパスを指定する。

データの保存先ディレクトリは以下のとおりである。
- macOS Web / Node.js環境: `~/Library/Application Support/GlassRelay`
- Linux Web / Node.js環境: `~/.local/state/glass-relay/service`
- macOSネイティブアプリ: `~/Library/Application Support/GlassRelay`

実機およびブラウザにおける動作検証の状況や未確認事項の詳細は `docs/verification.md` に記載している。すべてのハードウェアおよびOS環境での動作を保証するものではない。
