# コマンド手順

## 概要

ターミナル作業中の会話引継ぎ要求をRelay本体へ渡すためのCLIスクリプト（`scripts/relay.mjs`）の利用手順および設定方法を説明する。本スクリプトは、作業中のターミナルから最小限の引数指定でRelayへ引継ぎ候補を通知するために使用する。

## 連携スクリプトの実行手順

作業中のターミナルから以下のコマンドを実行する。

```bash
node scripts/relay.mjs --provider codex --note "設計をレビュー"
```

引数 `--provider` には対象のプロバイダ名（`codex` または `claude`）を指定し、`--note` には引継ぎ時の補足事項を指定する。

本スクリプトは、同一ホスト上の `~/.local/state/glass-relay/request.json` に対してパーミッション `0600` で選択要求ファイルを作成または更新する。このファイルには要求の識別情報のみを書き込み、会話本文の複製は行わない。Mac上のRelay本体は5秒間隔でこのファイルを読み取り、該当する会話候補を画面上に表示する。引継ぎと送信の決定はユーザーがRelayの画面上で確認した上で行う。

なお、ターミナルの任意プロンプト入力欄に入力された `/relay` などの文字列を自動検知して本スクリプトを呼び出す機構には対応していない。

## Claude Codeでの設定例

Claude Codeのカスタムコマンドとして登録する場合は、`~/.claude/commands/relay.md` を作成して以下のテンプレートを記述する。

```markdown
!`node ~/projects/glass-relay/scripts/relay.mjs --provider claude`
```

設定にあたっては、既存のコマンド定義ファイルを上書きしないよう確認した上で配置する。本スクリプトはセッションIDの自動推測を行わない。実行時のカレントディレクトリ（cwd）、ホスト名、指定されたプロバイダ情報をもとにログから対象セッションの候補を絞り込む。条件に一致するセッションが複数検出された場合は、Relayの画面上で対象を手動選択する。

WSL環境でClaude Codeを動かしている場合、Macローカルのファイルパスは参照できないため、WSL側のファイルシステム上にも本スクリプトを配置し、WSL内のパスを指定して実行する必要がある。

## Codex環境での利用と制約

Codex環境（CLIまたは常駐デーモン）から利用する場合は、カスタムプロンプトまたはスキル定義から本スクリプトを呼び出す設定を行う。

Codexにおけるツールの登録名やスクリプト実行時のユーザー承認フローは、利用しているクライアントUIの仕様に依存する。そのため、特定のコマンド名で汎用的に動作することは検証されていない。また、本手順は対話環境に標準で組み込まれた万能の `/relay` コマンドを完全に再現するものではない。
